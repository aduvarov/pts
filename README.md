## 13.5. Proxy

**Основная концепция:**

Паттерн "Прокси" представляет собой дополнительный слой между клиентом и реальным объектом, позволяющий контролировать доступ к этому объекту, добавляя при этом дополнительную логику.

**Проблема:**

-   Необходимость управления доступом к объекту API, например, Payment API.
-   Возникает потребность в кэшировании данных.

**Решение:**

1.  Реализация интерфейса IPayment API в классе Payment API Proxy.
2.  Внедрение реального Payment API в качестве зависимости в Payment API Proxy.
3.  Добавление в прокси дополнительной логики, например, кэширования или проверки прав доступа.

**Пример на практике:**

-   Создание интерфейса IPayment API с методом GetPaymentDetails.
-   Разработка класса, реализующего IPayment API, имитирующего базу данных платежей.
-   Создание прокси (PaymentAccessProxy), имплементирующего тот же интерфейс IPayment API.
-   Добавление в прокси логики проверки прав доступа перед делегированием вызова реальному Payment API.

**Преимущества прокси:**

-   Возможность контролировать доступ к объекту.
-   Добавление дополнительных действий перед обращением к объекту, например, логирование или кэширование.

**Использование:**

Прокси используется для безопасного доступа к ресурсам, добавления дополнительной логики обработки запросов и управления ресурсами.
