## 14.1. Поведенческие паттерны

### Введение

-   **Тема:** Поведенческие паттерны.
-   **Цель:** Решение задач эффективного взаимодействия между компонентами системы для упрощения масштабирования и поддержки.

### Основные паттерны:

1.  **Цепочка вызовов (Chain of Command)**
    -   Применение: В API с промежуточными обработчиками.
    -   Задача: Создать последовательность команд для обработки запросов.
2.  **Медиатор (Mediator)**
    -   Роль: Управление взаимодействием между компонентами.
    -   Особенность: Позволяет связывать компоненты в произвольном порядке.
3.  **Команда (Command)**
    -   Использование: В CQRS, стейт-менеджерах (например, Angular).
    -   Функция: Изоляция логики в команды для облегчения взаимодействия.
4.  **Состояние (State)**
    -   Применение: Управление состоянием объекта.
    -   Механизм: Стейт-машина с переходами между состояниями.
5.  **Стратегия (Strategy)**
    -   Цель: Позволяет менять алгоритмы на ходу.
    -   Преимущество: Обеспечивает гибкость в выборе стратегий.
6.  **Итератор (Iterator)**
    -   Описание: Упрощает итерацию по сложным коллекциям.
    -   Возможности: Итерация в разных направлениях (например, по дереву).
7.  **Шаблонный метод (Template Method)**
    -   Функция: Задаёт общий алгоритм с шагами, применимыми к разным системам.
8.  **Наблюдатель (Observer)**
    -   Принцип: Подписка на события или изменения для получения уведомлений.
    -   Применение: Широко используется в разных системах.
