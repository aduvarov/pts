## 12.2. Factory Method

**Цель Лекции:** Понять потребность в использовании паттерна "Фабрика" и научиться его реализовывать на TypeScript.

**Введение:**

-   Проблематика: При работе с различными страховыми компаниями возникает необходимость изменять систему под каждую из них, что ведет к избыточному коду и увеличению сложности системы.
-   Решение: Использование паттерна "Фабрика" позволяет абстрагироваться от конкретных классов страховок и унифицировать процесс их создания, упрощая расширение системы.

**Структура Паттерна "Фабрика":**

1.  **Общий интерфейс страховки (IInsurance):** Определяет структуру и методы, которые должны быть реализованы конкретными страховками.
2.  **Конкретные классы страховок (TFInsurance, ABAInsurance):** Реализуют интерфейс IInsurance, имеют уникальную логику отправки данных в API страховых компаний.
3.  **Абстрактный класс фабрики (Abstract Insurance Factory):** Определяет метод создания объекта страховки без конкретизации его класса.
4.  **Конкретные фабрики:** Фабрики, создающие объекты конкретных классов страховок (TF и ABA), наследуясь от абстрактной фабрики.

**Реализация на TypeScript:**

-   Использование интерфейса для описания структуры и методов страховки.
-   Создание конкретных классов страховок, имплементирующих этот интерфейс.
-   Применение абстрактного класса фабрики для определения общего метода создания страховок.
-   Определение конкретных фабрик для каждого типа страховки.

**Преимущества:**

-   Упрощение добавления новых типов страховок.
-   Разделение и инкапсуляция процесса создания объектов от их использования.
-   Унификация работы со страховками через общий интерфейс.

**Альтернативная Реализация:**

-   Без использования абстрактных классов и наследования, через мапу типов и универсальную фабрику. Это упрощает структуру, но уменьшает гибкость в добавлении специфической логики в конкретные фабрики.
