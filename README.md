## 14.6. Strategy

**Основные моменты:**

-   **Определение:** Стратегия - это поведенческий паттерн проектирования, который позволяет определять схожие алгоритмы и инкапсулировать их в отдельные классы для возможности их взаимозаменяемости во время исполнения программы.
-   **Пример использования:** Часто используется для различных способов авторизации в системе, где каждый метод авторизации (например, JVT, GitHub, Google Auth) имеет свою уникальную реализацию, но общий интерфейс.
-   **Реализация:**
    -   Создается интерфейс `AuthStrategy`, который определяет общий для всех стратегий метод `auth` для авторизации пользователя.
    -   Различные способы авторизации реализуют данный интерфейс (например, `JwtStrategy`, `GitHubStrategy`), имея свою уникальную логику проверки.
    -   В классе авторизации `Auth` вводится возможность установки текущей стратегии через конструктор или сеттер и использование её для проведения авторизации.
-   **Преимущества:** Упрощает расширяемость и изменяемость логики авторизации, избегая усложнения основного класса авторизации.
-   **Недостатки:** Требуется добавление дополнительного кода для управления стратегиями и определение момента для смены стратегий в зависимости от контекста.
