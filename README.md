## 13.4. Adapter

#### Введение в Паттерн "Адаптер":

-   Адаптер – это паттерн, позволяющий интегрировать в ваше приложение классы с несовместимыми интерфейсами.
-   Пример из жизни – использование переходника для подключения USB Type-C кабеля к USB 3.0 порту.

#### Проблема:

-   Есть код, работающий с Key-Value (KV) Database (например, In-Memory или Redis).
-   Требуется добавить поддержку Persistent Database для постоянного хранения данных.
-   Существующий код не совместим с новой базой данных из-за различий в методах.

#### Решение – Использование Адаптера:

-   Создаётся Адаптер, который наследует KV Database, чтобы обеспечить совместимость с существующим кодом.
-   Адаптер принимает в конструктор объект Persistent Database.
-   Адаптер переопределяет методы KV Database, адаптируя их для работы с Persistent Database.
-   В итоге, благодаря Адаптеру, можно использовать Persistent Database вместо KV Database без изменения клиентского кода.

#### Практический Пример:

1.  Имеется класс KV Database с методом `save`, принимающим ключ и значение.
2.  Клиентский код работает с данным классом.
3.  Создаётся класс Persistent Database с несовместимым методом `savePersistent`.
4.  Реализуется класс `PersistentDBAdapter`, расширяющий KV Database:
    -   Конструктор принимает объект Persistent Database.
    -   Метод `save` переопределён, чтобы делегировать вызов методу `savePersistent` с адаптацией данных.
5.  В клиентском коде, вместо прямой работы с KV Database, используется `PersistentDBAdapter` с передачей ему Persistent Database.

#### Вывод:

-   Паттерн "Адаптер" позволяет легко интегрировать в существующее приложение новые компоненты с различающимися интерфейсами.
-   Это обеспечивает гибкость и расширяемость приложения, позволяя использовать разнообразные внешние библиотеки и сервисы без значительных изменений в коде.
