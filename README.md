## 14.3. Mediator

## Цель паттерна

-   Развязать связанность между компонентами системы.
-   Централизовать обработку взаимодействий между компонентами.

## Проблема

Когда в системе компоненты сильно связаны, изменение в одном может привести к необходимости изменений в других.

## Решение

Использование паттерна "Медиатор" позволяет внедрить компонент-посредник, который управляет коммуникацией между другими компонентами, значительно снижая их взаимозависимость.

## Пример на практике

-   **Сценарий backend**: обработчик событий, отправка уведомлений, логирование, сброс кэша.
-   **Сценарий frontend**: кнопка "Отправить форму" должна инициировать отправку формы, не зная о полях формы.

## Реализация

1.  **Определить интерфейс медиатора** с методом `notify`, который будет уведомлять о событиях.
2.  **Создать классы для компонентов** системы (например, обработчик событий, логгер, отправка уведомлений).
3.  **Реализовать медиатор** с логикой координации взаимодействий между компонентами.

## Преимущества использования

-   Упрощение обновлений и поддержки кода за счёт снижения зависимости между компонентами.
-   Эффективное управление взаимодействиями в сложных системах.
