## 13.6. Composite

#### Цели и Задачи

Паттерн композита предназначен для упрощения работы с древовидными структурами данных, позволяя клиентам одинаково обращаться к индивидуальным объектам и их группам.

#### Пример Проблемы

Представим магазин с различными товарами и упаковками. Задача – определить общую стоимость заказа, включая стоимость доставки и товаров, распределенных по разным упаковкам.

#### Проблема Решения Традиционным Способом

Традиционный способ подразумевает сложную реализацию, с требованиями к пониманию внутренней структуры заказа и многочисленными условиями для обработки разных типов элементов. Это ведет к "мешанине" в коде и затрудняет дальнейшие модификации.

#### Решение с Помощью Композита

1.  **Абстракция DeliveryItem**: Создание абстрактного класса (или интерфейса) `DeliveryItem`, описывающего общий интерфейс для всех элементов (товары, упаковки, магазин) в иерархии.
    -   `addItem`: Метод для добавления новых элементов.
    -   `getPrice`: Абстрактный метод для получения стоимости.
2.  **Реализация Компонентов**: Создаются конкретные классы для разных типов элементов, такие как магазин, упаковка и товар, расширяющие абстрактный класс `DeliveryItem`.
    -   **DeliveryShop**: Реализует `getPrice`, суммируя стоимость всех элементов и добавляя стоимость доставки.
    -   **Package**: Реализует `getPrice`, агрегируя стоимость содержащихся в нем элементов.
    -   **Product**: Просто возвращает свою стоимость.
3.  **Преимущества Паттерна Композита**:
    -   Упрощает структуры данных, позволяя обращаться к одиночным объектам и составным объектам единообразно.
    -   Облегчает добавление новых типов элементов без изменения существующего клиентского кода.
    -   Повышает модульность и гибкость при проектировании системы.

#### Пример Применения

После определения структуры, заполним магазин товарами и упаковками с товарами, демонстрируя, как легко можно добавлять новые элементы и получать общую их стоимость.
