## 15.3. Наивная реализация

#### Цели Лекции:

-   Рассмотреть наивную реализацию проекта конвертации видео.
-   Идентифицировать основные проблемы подхода.
-   Обсудить пути улучшения и переход к масштабируемой архитектуре.

#### Ключевые Понятия:

-   **Наивная Реализация**: Код написан в одном файле; всего 43 строчки.
-   **Библиотека Inquirer**: Используется для получения ввода от пользователя.
-   **FFmpeg**: Утилита для работы с видео; используется через child process.
-   **Child Process**: Механизм Node.js для выполнения внешних команд.

#### Проблемы Наивной Реализации:

1.  **Ограниченная Гибкость**: Добавление новых настроек требует ручного обновления кода и изучения документации FFmpeg.
2.  **Нет Чёткого Разделения Задач**: Ввод данных, выполнение процесса и вывод результатов смешаны, что усложняет модификацию.
3.  **Сложность В Переключении Вывода**: Переключение между разными способами вывода результата (например, консоль на уведомление в телеграм) требует изменений в коде.
4.  **Отсутствие Масштабируемости**: Для добавления новых функций или утилит требуется значительное изменение текущей реализации.

#### Путь К Улучшению:

-   **Архитектурное Планирование**: Необходимо разработать план строительства приложения с чётким разделением функциональности на модули.
-   **Разделение Зон Ответственности**: Входные данные, процесс выполнения и вывод результатов должны быть изолированы друг от друга.
-   **Интерфейсы Для Взаимодействия**: Создание универсальных интерфейсов облегчает добавление новых функций и способов вывода информации.
