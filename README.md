## 13.1 Структурные паттерны

В этой лекции мы погрузимся в мир структурных паттернов проектирования, ключевые инструменты для построения и организации классов в вашем приложении. Понимание и использование структурных паттернов помогает создавать гибкую и эффективную архитектуру проекта.

### Основные паттерны:

1.  **Мост (Bridge)**
    -   **Задача**: Предотвращает необходимость создания раздутых иерархий классов, позволяя разделить абстракцию и реализацию, чтобы они могли развиваться независимо.
    -   **Применение**: Когда нужно разделить класс на две отдельные иерархии — одна для абстракции, другая для реализации.
2.  **Фасад (Facade)**
    -   **Задача**: Скрывает сложные системы за простым интерфейсом, обеспечивая легкий доступ к ним.
    -   **Применение**: Используется для упрощения взаимодействия с комплексными библиотеками или API.
3.  **Адаптер (Adapter)**
    -   **Задача**: Позволяет объектам с несовместимыми интерфейсами работать вместе.
    -   **Применение**: Применяется, когда нужно объединить функциональность различных классов с разными интерфейсами.
4.  **Прокси (Proxy)**
    -   **Задача**: Действует как посредник между клиентом и службой, контролируя доступ к объекту и позволяя добавлять дополнительные операции при обращении к объекту.
    -   **Применение**: Используется для контроля доступа, логирования запросов или кеширования результатов.
5.  **Композит (Composite)**
    -   **Задача**: Упрощает работу со сложными древовидными структурами, обращаясь к группам объектов так же, как и к отдельным объектам.
    -   **Применение**: Применим в ситуациях, когда нужно единообразно обрабатывать как отдельные объекты, так и их группы.
