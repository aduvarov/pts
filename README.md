## 14.8. Template Method

## Цель паттерна

Паттерн "Шаблонный метод" используется для определения скелета алгоритма, допуская отдельные шаги алгоритма быть изменены подклассами. Это позволяет переиспользовать код и избегать дублирования.

## Пример использования

Рассмотрим ситуацию, где у нас есть форма, которую необходимо отправить через несколько разных API. Подход без паттерна потребовал бы дублирования кода для каждого API.

### Базовая идея паттерна

-   Создаем абстрактный класс, определяющий скелет алгоритма (в нашем случае отправку формы через API).
-   В подклассах реализуем изменяемые части алгоритма (конкретное API).

### Шаги реализации

1.  **Определение абстрактного класса**: Создаем абстрактный класс с шаблонным методом, включающим последовательные шаги: подготовка данных, логгирование, отправка.
2.  **Реализация шагов**: Определение абстрактных методов для изменяемых шагов (например, подготовка данных под конкретное API) и реализация общих шагов (логгирование).
3.  **Создание конкретных подклассов**: Подклассы реализуют специфическую логику для каждого API, следуя шаблонному методу абстрактного класса.

### Пример кода

-   Абстрактный класс `SaveForm` с шаблонным методом `save` и методами `fill`, `log`, `send`.
-   Конкретные классы для каждого API (`FirstAPI`, `SecondAPI`), реализующие методы `fill` и `send`.

### Преимущества паттерна

-   Избегание дублирования кода при реализации общих шагов алгоритма.
-   Упрощение поддержки и изменения кода за счет ясного разделения ответственности между общими и специфическими шагами.
