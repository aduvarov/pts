## 14.4. Command

**Основная идея паттерна "Команда":**

-   Паттерн "Команда" позволяет инкапсулировать запрос в виде объекта, тем самым давая возможность параметризировать клиентов с другими запросами, ставить операции в очередь, логировать их, а также поддерживать отмену операций.

**Примеры использования:**

-   Стейт менеджеры (например, NGXS для Angular).
-   CQRS (Command Query Responsibility Segregation) - разделение команд и запросов.

**Практический пример:** Имеется сервис пользователей (`UserService`), взаимодействующий с различными точками входа (контроллером, веб-сокетом). Предположим, требуется добавить логирование, выполнение операций по расписанию и возможность отмены добавления пользователя.

**Традиционный подход:**

-   Непосредственный вызов методов `UserService` из контроллеров и других точек входа.
-   Реализация логики отмены, логирования и пр. в каждой точке входа.

**Подход с использованием паттерна "Команда":**

-   Создаётся отдельный класс команды (например, `AddUserCommand`), который инкапсулирует в себе всю логику добавления пользователя.
-   Класс команды имеет метод `execute()`, который выполнит необходимые действия (например, добавит пользователя).
-   Возможность отмены операции (`undo()`) реализуется в классе команды.
-   Создаётся история выполненных команд, что позволяет легко отслеживать последовательность операций и при необходимости отменять их.

**Преимущества использования паттерна "Команда":**

-   Уменьшает связанность системы за счёт отделения логики выполнения операций от её инициатора.
-   Упрощает добавление новых операций и управление ими.
-   Облегчает реализацию дополнительных функций, таких как логирование и отмена операций.
