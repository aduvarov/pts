## 14.5. State

**Цель лекции:** Понять, как работает паттерн состояние и как его реализовать на примере публикации статьи.

#### Введение

-   Паттерн состояние помогает управлять состоянием объекта.
-   Примером использования может служить процесс публикации статьи с состояниями: черновик, модерация, опубликовано.

#### Проблема без использования паттерна состояние

-   В традиционном подходе управление состояниями объекта сопровождается множеством условий (if/else или switch).
-   Это затрудняет добавление новых состояний и усложняет код.

#### Решение: Паттерн Состояние

1.  **Определение базовых компонентов:**
    -   Создаём класс `Document`, представляющий наш документ со свойствами и методами управления состоянием (`publishDoc`, `deleteDoc`).
    -   Определяем абстрактный класс `DocumentState` для описания общего интерфейса состояний.
2.  **Реализация конкретных состояний:**
    -   Создаём классы для каждого состояния (`DraftDocumentState`, `PublishedDocumentState`), наследующиеся от `DocumentState`.
    -   В каждом классе состояния переопределяем необходимые методы управления состоянием (напр., `publish`, `delete`), добавляем логику переходов между состояниями.
3.  **Изменение состояния документа:**
    -   В классе `Document` добавляем методы `getState` и `setState` для управления текущим состоянием.
    -   При изменении состояния создаём новый объект соответствующего класса состояния и обновляем ссылку на текущее состояние.

#### Преимущества использования паттерна Состояние

-   **Чистая логика управления состоянием:** Вся логика связанная с конкретным состоянием, находится в классе этого состояния.
-   **Упрощение добавления новых состояний:** Для добавления нового состояния достаточно создать новый класс и определить в нём необходимую логику.
-   **Читабельность и поддержка кода:** Разделение логики по классам состояний делает код более читабельным и упрощает его поддержку.
