## 12.3. Singleton

**Основная цель паттерна "Синглтон" (Одиночка):** Обеспечить создание только одного экземпляра класса в приложении, что позволяет глобальный доступ к этому экземпляру.

**Пример проблемы, решаемой синглтоном:**

-   Имеются два сервиса, которые хотят использовать общие данные через третий сервис.
-   Это может быть полезно для реализации кэша или обмена данными между компонентами.

**Реализация:**

1.  **Закрытие конструктора класса:** Сделать конструктор приватным, чтобы предотвратить создание экземпляров класса с помощью оператора `new` извне класса.
2.  **Создание приватной статической переменной:** Для хранения единственного экземпляра класса.
3.  **Создание публичного статического метода для доступа к экземпляру:** Этот метод проверяет, существует ли уже экземпляр класса, и если нет, создает его. Потом возвращает ссылку на этот экземпляр.

**Пример кода:**

```typescript
class MyMap {
    private static instance: MyMap
    private constructor() {}

    public static get(): MyMap {
        if (!MyMap.instance) {
            MyMap.instance = new MyMap()
        }
        return MyMap.instance
    }

    // Пример бизнес-логики
    public clean() {
        // Логика очистки
    }
}
```

**Применение на практике:**

-   Использование синглтона для обмена данными (например, два сервиса используют общий кэш).
-   Различные инстансы класса могут вызвать метод get() и получат доступ к одному и тому же экземпляру MyMap.
-   Метод clean() в классе MyMap может использоваться для выполнения специфической бизнес-логики, доступной через глобальный экземпляр.

**Заключение:**

-   Паттерн Синглтон важен для обеспечения того, чтобы класс имел только один экземпляр в рамках приложения, что можно использовать для различных целей, в том числе для предотвращения дублирования данных, обмена данными между различными компонентами программы или сохранения состояния.
-   Во многих фреймворках реализация синглтона скрыта от пользователя и управляется через dependency injection.
